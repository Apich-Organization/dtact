## 2025-01-28 - Optimizing Atomic Loads in Scheduler Hot Loops
**Learning:** In the Dtact scheduler (`src/dta_scheduler.rs`), the local worker's `local_head` atomic pointer is immutable during certain operations like `poll_mailboxes` and `drain_warehouse`. Re-reading it from memory on every loop iteration to calculate the queue capacity adds unnecessary atomic load overhead.
**Action:** When working with high-frequency queues where one side is unchanged by the current thread, hoist the atomic read out of the loop. Pass this cached value down via a helper like `local_queue_len_with_head` to avoid redundant memory operations and improve throughput without sacrificing readability. Also ensuring that you only checkout lock files prior to committing since `cargo test` automatically updates it without `--locked`.
