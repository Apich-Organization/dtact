## 2024-03-24 - Hoisting Immutable Atomics out of Scheduler Hot Loops
**Learning:** In Dtact's `dta_scheduler.rs`, high-frequency loops (like `drain_warehouse` and `poll_mailboxes` polling loops) perform queue length checks. The local queue length calculation needs `local_tail` (which changes during pushes) and `local_head` (which does not, as the current worker is the only consumer and we are only *pushing* work in these contexts). Repeatedly loading `local_head` natively in a tight loop is an unnecessary atomic read operation on an invariant.
**Action:** Always identify invariant atomic reads inside hot paths, hoist the `load` outside the loop to cache the value (`fixed_head`), and pass it into inner functions explicitly (like adding `fixed_head` as an argument to `route_chunk`) to avoid redundant atomic operations.
