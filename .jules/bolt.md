## 2024-11-20 - [Redundant atomic reads caching]
**Learning:** In `dta_scheduler.rs`, variables like `local_head` are immutable during specific functions (`poll_mailboxes`, `drain_warehouse`). Continuously calling `local_queue_len()` involves redundant atomic `load` operations of `local_head` inside inner loops, which creates CPU overhead. Passing pre-computed lengths to functions (like `route_chunk`) bypasses safety checks because the queue can grow and make the pre-calculated length stale.
**Action:** Instead of calling `local_queue_len()` inside loops or functions, cache the immutable `local_head` once before the loop (using `Ordering::Relaxed`), and pass `fixed_head` down to functions. Then, calculate the current length dynamically within the functions/loops by using `fixed_head` alongside a fresh `local_tail` load. This reduces redundant atomic reads while preserving capacity safety checks.
