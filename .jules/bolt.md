## 2024-06-25 - Cache local_head in scheduler hot paths
**Learning:** In SPSC/MPMC queues where one side (head or tail) is not modified by the current thread in a loop, repeatedly loading it via `AtomicUsize::load` wastes cycles. `worker.local_queue_len()` encapsulates both head and tail loads, hiding this redundancy when called inside a high-frequency loop (like `poll_mailboxes` and `drain_warehouse`).
**Action:** Hoist the atomic load of the unchanging pointer (like `local_head` for a consumer that is only pushing) outside the loop. Pass this cached value down to helper functions (like `route_chunk`) instead of calling the encapsulated `len()` method, but be careful to calculate the fresh length inside the helper rather than passing a stale pre-calculated length, as queue sizes can change dynamically if other helpers modify the opposing pointer.
