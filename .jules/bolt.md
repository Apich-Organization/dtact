## 2024-05-24 - [Avoid Redundant Atomic Loads in Hot Paths]
**Learning:** In highly contentious MPMC or SPSC queues within hot scheduling loops, even an `Ordering::Relaxed` load on a shared cache line (like `local_tail`) carries an overhead. If a loop already tracks a queue's length and starting head via other mechanisms (like in `poll_mailboxes` using `added`), it is possible to compute the exact tail offset mathematically (e.g. `(head + len) & MASK`) and pass it to helper functions instead of letting the helper perform a redundant atomic load.
**Action:** When working on extreme latency-sensitive paths like a thread pool scheduler, explicitly hoist dependent atomic loads up the call stack if their value can be purely derived from already-cached loop invariants. Pass the pre-calculated state rather than re-evaluating it.
