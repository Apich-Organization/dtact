## 2024-05-24 - [Avoid Redundant Atomic Loads in Hot Pushing Loops]
**Learning:** [In hot scheduling loops with SPSC queues where only the current worker thread writes to the tail (e.g., `Worker::push_batch`), repeatedly calling `tail.load(Ordering::Relaxed)` introduces unnecessary memory loads. Even though it's relaxed, it prevents the compiler from optimizing across function calls and introduces read-after-write memory dependencies. We can calculate the tail perfectly from cached loop invariants: `tail = (fixed_head + cur_len) & MASK`.]
**Action:** [Whenever routing/pushing to local queues in loops, precompute the destination index (tail) mathematically from existing invariants instead of relying on internal atomic load calls, and pass the computed value down to the push functions.]
