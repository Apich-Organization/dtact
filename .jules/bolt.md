## 2023-11-01 - Redundant Atomic Loads in SPSC Queues
**Learning:** In hot Rust code paths (like single-producer single-consumer queues), checking `head == tail` using sequential atomic loads in a loop can cause redundant memory operations. If a thread-local value is modified indirectly within the loop (e.g., via helpers pushing new items), the loop still needs to refresh its view, but reloading unconditionally every iteration can be inefficient.
**Action:** When a loop iterates while `head != tail`, cache `tail` locally before the loop, and only reload `tail` from atomic memory when `head == tail`. If they still match after the reload, then the queue is genuinely empty and the loop can safely break. This prevents redundant loads of `tail` while preserving correct synchronization for newly enqueued items.
